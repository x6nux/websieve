# 阶段 6：TUN 与 fake-ip — 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用 `netstack-smoltcp` + `tun-rs` 建立 TUN 入口，配套 fake-ip DNS 服务器与动态 bypass 路由，并把启动顺序钉死为可测的纪律。TUN 只是**又一个入口**——阶段 1 的路由层与阶段 2 的出站层原样复用，不新建任何平行通路。

**Architecture:** 新增一个纯逻辑 crate `wsieve-tun`（零 Tauri 依赖、判决全是纯函数，因此可穷举单测），以及 `src-tauri` 侧一层薄编排。crate 内部四块彼此独立：`fakeip`（域名 ⇄ 假 IP 映射）、`fakedns`（DNS 判决，纯函数）、`bypass`（动态绕行名单）、`routes`（路由表命令构造）。需要 root 的只有两件事——创建 utun 设备、写路由表——它们被隔离在 trait 后面（`TunStage` / `RouteBackend`），因此**顺序纪律与环路防线都能在无 root 环境下单测**。

**Tech Stack:** Rust 2021 · `netstack-smoltcp` 0.2.4 · `tun-rs` 2.8.8（features `async`, `async_framed`）· `hickory-proto` 0.26（DNS 报文编解码）· macOS `route`(8)

**依据:** `docs/superpowers/specs/2026-08-24-client-routing-and-ui-design.md` §4.2 §7.1 §7.2 §8.3 §10 §12 §13 §14 §15

## 两个陷阱（这是本阶段难的全部原因）

### 陷阱 1 — 路由环路（§8.3.1）

TUN 捕获全部流量，**包括转发器连向真实服务器 IP 的那条**：

```
WebView → 127.0.0.1:18443（环回，不过 TUN ✓）
  → 转发器 → 真实服务器 IP:443
      → 被 TUN 捕获 → 路由层判「走代理」
          → 出站 → WebView → 127.0.0.1:18443
              ↺ 死循环
```

解法是标配的「服务器地址绕行」。**websieve 的特殊之处**：该 IP 是
`shard.rs:90 resolve_upstream` 在**运行时**解析得到的，因此 bypass 名单
必须动态维护，并随出站增删而增删。这就是 Task 3 的 `BypassSet` 存在的
全部理由。

> **已实证**：netstack 自己**不会**替我们避开环路。Task 8 的
> `netstack_does_not_filter_server_ip_by_itself` 把一个发往服务器 IP 的
> SYN 喂进协议栈，`TcpListener` 原样把它当成一条连接吐出来。
> **bypass 是唯一防线。**

### 陷阱 2 — DNS 顺序（§8.3.2）

```
解析真实 IP → 写 bypass 路由 → 起转发器 → 写 hosts → 最后拉起 TUN
```

TUN 的 DNS 劫持若先生效，`resolve_upstream` 拿到的就是 `198.18.x.x`，
转发器连向虚空——而日志上什么异常都没有。

顺序纪律怎么变成可测的东西：把每一步记进一条时间线，编排函数只负责按序
追加，测试直接断言序列（Task 9）。**还要写反例测试**：故意先拉 TUN，
断言解析确实中毒——证明这条纪律不是形式主义。

## 平台范围：**macOS 优先，明确声明**

三个平台的设备创建与路由操作差异极大，本阶段**只完整实现 macOS**，
其余两个平台留下编译期占位并在 UI 明示「本平台 TUN 暂不可用」。

| 平台 | 设备创建 | 提权 | 路由表 | 本阶段 |
|---|---|---|---|---|
| **macOS** | `utun`（`socket(PF_SYSTEM, SOCK_DGRAM, SYSPROTO_CONTROL)`，见 `tun-rs/src/platform/macos/tuntap.rs:58`） | **需 root** | `route`(8) 子进程 | ✅ 完整实现 |
| Linux | `/dev/net/tun` | `CAP_NET_ADMIN` 或 root | netlink（或 `ip route` 子进程） | ⏸ 占位 |
| Windows | wintun.dll | 管理员 | `IPHLPAPI` / `netsh` | ⏸ 占位 |

**为什么不全做**：路由表操作三套实现、提权模型三套、测试环境三套，而
两个陷阱的逻辑是**平台无关**的。先把陷阱在一个平台上彻底解决，其余平台
是纯粹的机械移植。跨平台化时唯一需要改的是 `RouteBackend` 的实现与
`spawn_netstack()` 的 `cfg` 分支——两处都已经在 trait 后面。

### macOS 提权：本阶段的取舍

**本阶段不实现提权，要求用户以 `sudo` 运行。** 理由：

- 项目已有先例——`hosts` 写入同样需要管理员，现有做法是**不可写就降级**
  并在日志里告诉用户怎么办（`shard_setup.rs:110`）。TUN 沿用同一套姿态
- 打包 privileged helper（`SMJobBless` / `SMAppService`）需要 Apple
  Developer ID 签名与一个独立的 helper 二进制。而 `tauri.conf.json` 当前
  `"bundle": { "active": false }`——**项目还没有打包流程**，helper 无处安放
- ponytail：先让 `sudo` 版本跑通并验证两个陷阱都解掉了，再谈提权 UX

> `ponytail:` TUN 提权靠 `sudo`。**上限**：用户必须从终端启动，图形化
> 双击运行时 TUN 不可用（降级为「TUN 已禁用」+ UI 提示）。**升级路径**：
> 打包流程建立后引入 `SMAppService` 注册的 privileged helper，把创建
> utun 与写路由两件事挪进去，主进程通过 XPC 请求；`RouteBackend` 与
> `TunStage` 两个 trait 就是为此预留的接缝。

**权限检测必须在拉起 TUN 之前做**，且失败**不静默降级**——静默降级会让
用户以为 TUN 开着而实际全部流量在裸奔（与 §6.4「禁止回退直连」同源）。

放在测试模块**之前**：

```rust
//! fake-ip 池：域名 ⇄ 保留段假 IP 的双向映射（设计文档 §7.1 第二层）。
//!
//! TUN 只看得到 IP 包。要让路由层拿回域名做判决，唯一办法是先在 DNS 层
//! 发一个假 IP，再在 TUN 层反查回来。范围固定 `198.18.0.0/15`
//! （RFC 2544 基准测试保留段，公网不会出现，撞不上真实目标）。
//!
//! **出站服务器域名必须自动进 filter**（§7.2 纪律①）：它们一旦拿到 fake-ip，
//! 转发器就会连向虚空。用户不该需要记住这件事。

use std::collections::HashMap;
use std::net::Ipv4Addr;
use std::sync::Mutex;

/// 198.18.0.0/15 的首尾（含）。前 4 个地址留作网络号与保留用途，不分配。
const RANGE_START: u32 = u32::from_be_bytes([198, 18, 0, 4]);
const RANGE_END: u32 = u32::from_be_bytes([198, 19, 255, 254]);

/// fake-ip 分配与反查。
///
/// ponytail: 池满时直接从头轮转覆盖最老的映射，不做 LRU 淘汰。
/// 上限 = 13 万个域名同时在用；到那之前轮转不会撞上仍在使用的条目。
/// 升级路径：给 `by_ip` 加时间戳并在轮转时跳过 60s 内活跃的条目。
pub struct FakeIpPool {
    inner: Mutex<Inner>,
    filter: Vec<String>,
}

struct Inner {
    next: u32,
    by_domain: HashMap<String, Ipv4Addr>,
    by_ip: HashMap<Ipv4Addr, String>,
}

impl FakeIpPool {
    /// `filter` 是不参与 fake-ip 的域名后缀集合。出站服务器域名由调用方
    /// （TUN 编排层）**自动**加入，见 `with_server_domains`。
    pub fn new(filter: Vec<String>) -> Self {
        Self {
            inner: Mutex::new(Inner {
                next: RANGE_START,
                by_domain: HashMap::new(),
                by_ip: HashMap::new(),
            }),
            filter: filter.into_iter().map(|s| normalize(&s)).collect(),
        }
    }

    /// 把出站服务器域名并入 filter。**这是纪律①的落点**：配置里
    /// `fake-ip-filter` 写没写都不影响，服务器域名一律进。
    pub fn with_server_domains(mut self, domains: &[String]) -> Self {
        for d in domains {
            let n = normalize(d);
            if !self.filter.contains(&n) {
                self.filter.push(n);
            }
        }
        self
    }

    /// 该域名是否被排除在 fake-ip 之外（应走真实解析）。
    pub fn is_filtered(&self, domain: &str) -> bool {
        let d = normalize(domain);
        self.filter.iter().any(|f| {
            // 通配后缀 `*.example.com` 与裸后缀 `example.com` 都按后缀匹配，
            // 且必须落在点边界上 —— `notexample.com` 不该被 `example.com` 命中。
            let f = f.strip_prefix("*.").unwrap_or(f);
            d == *f || d.ends_with(&format!(".{f}"))
        })
    }

    /// 取（或分配）该域名的 fake-ip。filter 命中时返回 `None`，调用方
    /// 转真实解析。
    pub fn allocate(&self, domain: &str) -> Option<Ipv4Addr> {
        if self.is_filtered(domain) {
            return None;
        }
        let key = normalize(domain);
        let mut g = self.inner.lock().expect("fakeip 锁中毒");
        if let Some(ip) = g.by_domain.get(&key) {
            return Some(*ip);
        }
        let ip = Ipv4Addr::from(g.next);
        g.next = if g.next >= RANGE_END { RANGE_START } else { g.next + 1 };
        // 轮转覆盖：先摘掉该 IP 的旧主人，避免反查指向已失效的域名。
        if let Some(old) = g.by_ip.insert(ip, key.clone()) {
            g.by_domain.remove(&old);
        }
        g.by_domain.insert(key, ip);
        Some(ip)
    }

    /// 反查：TUN 拿到目的 IP 时用它换回域名做路由判决。
    pub fn lookup(&self, ip: Ipv4Addr) -> Option<String> {
        self.inner
            .lock()
            .expect("fakeip 锁中毒")
            .by_ip
            .get(&ip)
            .cloned()
    }

    /// 该 IP 是否落在 fake-ip 段内（不论是否已分配）。
    pub fn in_range(ip: Ipv4Addr) -> bool {
        let v = u32::from(ip);
        (RANGE_START..=RANGE_END).contains(&v)
    }
}

/// 统一小写并去掉根点，让 `Example.COM.` 与 `example.com` 是同一个键。
fn normalize(d: &str) -> String {
    d.trim_end_matches('.').to_ascii_lowercase()
}

```rust
//! TUN bypass 集合：转发器出网连接的「绕行名单」。
//!
//! 环路陷阱（设计文档 §8.3.1）：TUN 捕获全部流量，**包括转发器连向真实
//! 服务器 IP 的那条**。若不绕行，该连接会被路由层判「走代理」，转身又回到
//! WebView → 127.0.0.1:18443，形成死循环。
//!
//! websieve 的特殊之处：服务器 IP 是 `shard.rs:90 resolve_upstream` 在
//! **运行时**解析得到的，因此名单必须动态维护，随出站增删而增删。

use std::collections::BTreeMap;
use std::net::IpAddr;
use std::sync::{Arc, RwLock};

/// 动态 bypass 名单。按出站 id 分组持有，便于出站下线时精确摘除。
///
/// 用 `BTreeMap` 而非 `HashMap`：条目数是个位数，有序遍历让 `snapshot()`
/// 结果稳定，路由表 diff 与测试断言都因此可复现。
#[derive(Clone, Default)]
pub struct BypassSet {
    inner: Arc<RwLock<BTreeMap<String, Vec<IpAddr>>>>,
}

impl BypassSet {
    pub fn new() -> Self {
        Self::default()
    }

    /// 登记某出站解析出的服务器 IP。同 id 重复调用即覆盖（幂等）。
    pub fn insert(&self, outbound_id: &str, ips: Vec<IpAddr>) {
        self.inner
            .write()
            .expect("bypass 锁中毒")
            .insert(outbound_id.to_string(), ips);
    }

    /// 出站下线时摘除。返回被摘掉的 IP，供调用方删对应路由。
    pub fn remove(&self, outbound_id: &str) -> Vec<IpAddr> {
        self.inner
            .write()
            .expect("bypass 锁中毒")
            .remove(outbound_id)
            .unwrap_or_default()
    }

    /// 该 IP 是否应绕过 TUN 直连物理网卡。
    ///
    /// **这是环路的唯一防线**，路由层在做任何规则判断之前先问这一句。
    pub fn contains(&self, ip: &IpAddr) -> bool {
        self.inner
            .read()
            .expect("bypass 锁中毒")
            .values()
            .any(|v| v.contains(ip))
    }

    /// 当前全部 bypass IP（去重、有序）。写路由表用。
    pub fn snapshot(&self) -> Vec<IpAddr> {
        let g = self.inner.read().expect("bypass 锁中毒");
        let mut all: Vec<IpAddr> = g.values().flatten().copied().collect();
        all.sort();
        all.dedup();
        all
    }

    pub fn is_empty(&self) -> bool {
        self.inner.read().expect("bypass 锁中毒").is_empty()
    }
}
```

```rust
//! fake-ip DNS 服务器：TUN 模式下拦截系统 DNS 查询（设计文档 §7.1 第二层）。
//!
//! 只做一件事：A 查询 → 分配 fake-ip 并**立即**应答（零网络往返）。
//! 真实解析推迟到出站层 —— 服务端离目标更近，且不受本地污染（§6.3）。
//!
//! 三类查询不给 fake-ip：
//!   1. `fake-ip-filter` 命中（含自动并入的出站服务器域名，§7.2 纪律①）
//!   2. AAAA —— 返回空应答（NOERROR + 0 answer），逼客户端退回 IPv4。
//!      给 IPv6 也发假地址意味着要再开一个 fake 段并让 netstack 双栈，
//!      收益为零
//!   3. 非 A/AAAA（MX / TXT / SRV…）—— 交给真实解析器
//!
//! **hickory 0.26 API 提示**：`Message` 的字段是公开的，0.24 时代的
//! `set_authoritative()` / `id()` 之类的存取器已移除，直接读写
//! `msg.metadata.*` / `msg.queries` / `msg.answers`。

use std::net::Ipv4Addr;
use std::sync::Arc;

use hickory_proto::op::{Message, OpCode, ResponseCode};
use hickory_proto::rr::rdata::A;
use hickory_proto::rr::{Name, RData, Record, RecordType};

use crate::fakeip::FakeIpPool;

/// fake-ip 记录的 TTL。取 1s：映射本就在本地，客户端缓存久了只会让
/// 我们无法及时回收；1s 也足以避免同一次页面加载重复查询。
const FAKE_TTL: u32 = 1;

/// 一次查询的处置结果。把「决定」与「发包」分开，判决逻辑因此可穷举单测。
#[derive(Debug, PartialEq, Eq)]
pub enum Answer {
    /// 直接以 fake-ip 应答。
    Fake(Ipv4Addr),
    /// 空应答（NOERROR，0 条记录）。AAAA 走这里。
    Empty,
    /// 交给上游真实解析器（filter 命中的 A 查询、以及其余记录类型）。
    Upstream,
}

pub struct FakeDns {
    pool: Arc<FakeIpPool>,
}

impl FakeDns {
    pub fn new(pool: Arc<FakeIpPool>) -> Self {
        Self { pool }
    }

    /// 判决单条查询。纯函数，不碰网络。
    pub fn decide(&self, name: &str, qtype: RecordType) -> Answer {
        match qtype {
            RecordType::A => match self.pool.allocate(name) {
                Some(ip) => Answer::Fake(ip),
                // filter 命中：必须走真实解析。出站服务器域名走的正是这条，
                // 拿到假 IP 的话转发器会连向虚空（§7.2 纪律①）。
                None => Answer::Upstream,
            },
            // fake-ip 只发 IPv4。空应答让客户端退回 A 查询。
            RecordType::AAAA => Answer::Empty,
            _ => Answer::Upstream,
        }
    }

    /// 把请求报文变成应答报文。返回 `Ok(None)` 表示本层不应答，
    /// 调用方转发给上游解析器。
    ///
    /// 报文解析失败**不静默丢弃**：返回错误让调用方记日志，否则客户端
    /// 要等到超时，表现为「莫名其妙全网卡顿」而不是一个可见的故障。
    pub fn respond(&self, req: &[u8]) -> Result<Option<Vec<u8>>, DnsError> {
        let msg = Message::from_vec(req).map_err(|_| DnsError::Malformed)?;
        let Some(q) = msg.queries.first() else {
            let err = Message::error_msg(msg.metadata.id, OpCode::Query, ResponseCode::FormErr);
            return Ok(Some(err.to_vec().map_err(|_| DnsError::Encode)?));
        };
        let name = q.name().to_ascii();
        match self.decide(&name, q.query_type()) {
            Answer::Upstream => Ok(None),
            Answer::Empty => Ok(Some(self.build(&msg, None)?)),
            Answer::Fake(ip) => Ok(Some(self.build(&msg, Some(ip))?)),
        }
    }

    fn build(&self, req: &Message, ip: Option<Ipv4Addr>) -> Result<Vec<u8>, DnsError> {
        let mut resp = Message::response(req.metadata.id, OpCode::Query);
        resp.add_queries(req.queries.iter().cloned());
        // 我们就是这些名字的权威：映射由本进程分配，不存在更上级来源。
        resp.metadata.authoritative = true;
        resp.metadata.recursion_desired = req.metadata.recursion_desired;
        resp.metadata.recursion_available = true;
        if let (Some(ip), Some(q)) = (ip, req.queries.first()) {
            let name: Name = q.name().clone();
            resp.add_answer(Record::from_rdata(name, FAKE_TTL, RData::A(A(ip))));
        }
        resp.to_vec().map_err(|_| DnsError::Encode)
    }
}

#[derive(Debug, thiserror::Error, PartialEq, Eq)]
pub enum DnsError {
    #[error("DNS 报文无法解析")]
    Malformed,
    #[error("DNS 应答编码失败")]
    Encode,
}
```

```rust
//! DNS 服务器的监听与转发（设计文档 §7.1 第二层的 IO 部分）。
//!
//! 判决逻辑全在 `fakedns::FakeDns`（纯函数、可穷举单测）。本模块只负责：
//! 收包 → 问判决 → 要么直接回、要么转给上游解析器再回。
//!
//! **端口选择**：监听 `127.0.0.1:53` 需要 root（<1024）。但 TUN 模式本就
//! 要 root，二者同生共死，因此不额外引入权限需求。开发/测试用高端口。

use std::net::SocketAddr;
use std::sync::Arc;

use tokio::net::UdpSocket;

use crate::fakedns::FakeDns;

/// DNS 报文的最大长度。EDNS0 之前是 512；我们的应答都很小，
/// 但请求可能带 OPT，取 1232（DNS flag day 2020 的建议值）足够。
const MAX_DNS: usize = 1232;

pub struct DnsServer {
    fake: Arc<FakeDns>,
    /// 上游真实解析器。filter 命中的查询原样转发过去。
    upstream: SocketAddr,
}

impl DnsServer {
    pub fn new(fake: Arc<FakeDns>, upstream: SocketAddr) -> Self {
        Self { fake, upstream }
    }

    /// 在 `listen` 上跑起来。返回实际绑定的地址（传 :0 时有用）。
    pub async fn serve(self: Arc<Self>, listen: SocketAddr) -> std::io::Result<SocketAddr> {
        let sock = Arc::new(UdpSocket::bind(listen).await?);
        let local = sock.local_addr()?;
        tokio::spawn(async move {
            let mut buf = vec![0u8; MAX_DNS];
            loop {
                let (n, from) = match sock.recv_from(&mut buf).await {
                    Ok(v) => v,
                    Err(e) => {
                        tracing::warn!("DNS 收包失败: {e}");
                        continue;
                    }
                };
                let req = buf[..n].to_vec();
                let this = self.clone();
                let sock = sock.clone();
                tokio::spawn(async move {
                    if let Err(e) = this.handle(&sock, &req, from).await {
                        // 不静默：DNS 悄悄失败的表现是「整机网络莫名其妙变慢」。
                        tracing::warn!("处理来自 {from} 的 DNS 查询失败: {e}");
                    }
                });
            }
        });
        Ok(local)
    }

    async fn handle(
        &self,
        sock: &UdpSocket,
        req: &[u8],
        from: SocketAddr,
    ) -> anyhow::Result<()> {
        match self.fake.respond(req)? {
            // 本层直接应答：零网络往返。
            Some(resp) => {
                sock.send_to(&resp, from).await?;
            }
            // filter 命中或非 A/AAAA：转给上游真实解析器。
            None => {
                let resp = self.forward(req).await?;
                sock.send_to(&resp, from).await?;
            }
        }
        Ok(())
    }

    /// 转发给上游并等应答。硬超时 2s（§7.3），超时即报错，
    /// 让客户端自己重试，而不是把连接吊在这里。
    async fn forward(&self, req: &[u8]) -> anyhow::Result<Vec<u8>> {
        let up = UdpSocket::bind(("0.0.0.0", 0)).await?;
        up.connect(self.upstream).await?;
        up.send(req).await?;
        let mut buf = vec![0u8; MAX_DNS];
        let n = tokio::time::timeout(std::time::Duration::from_secs(2), up.recv(&mut buf))
            .await
            .map_err(|_| anyhow::anyhow!("上游 {} 解析超时（2s）", self.upstream))??;
        buf.truncate(n);
        Ok(buf)
    }
}
```

> 地址在 macOS 上可读 `scutil --dns` 或 `/etc/resolv.conf`。
> **ponytail**：本阶段先接受一个显式配置的 IP（如 `223.5.5.5`），
> **上限**是用户换网络（公司内网 → 家里）时内网域名解析不了；
> **升级路径**是阶段 3 的 bootstrap 解析器已经要解决同一问题，
> 直接复用它，本模块只留一个 `upstream` 注入点。

|---|---|---|

原封不动——崩溃后系统立刻恢复正常上网。这与 §10「崩溃后必须能恢复」
同一条纪律，只是这次靠的是路由前缀语义而非清理逻辑。

//! TUN 路由表托管（设计文档 §10 的第三个 `ManagedSystemState` 实现）。
//!
//! 两类路由，职责完全不同：
//!
//! | 类别 | 内容 | 目的 |
//! |---|---|---|
//! | **默认路由** | `0/1` + `128/1` 指向 TUN | 抢在系统 `default` 之前接管全部流量。用两条 /1 而不是改 `default`，是因为改 `default` 会把原网关记录冲掉，崩溃后恢复不了 |
//! | **bypass 路由** | 每个服务器 IP 一条 `-host` 指向**物理网关** | 环路防线（§8.3.1）。转发器出网连接因此不进 TUN |
//!
//! 命令构造与执行分开：`argv()` 是纯函数可穷举单测；执行需要 root，
//! 只能人工验证（见计划的手工验证清单）。

use std::net::IpAddr;

/// 一条待写入的路由。
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct RouteEntry {
    /// 目的网段，`net/prefix` 或单个 host。
    pub dest: String,
    /// 下一跳。
    pub gateway: String,
}

/// 平台无关的路由动作。
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum RouteOp {
    Add,
    Delete,
}

/// 构造 macOS `route` 命令的参数向量。
///
/// `-q` 抑制正常输出但**不抑制退出码**，错误仍能被发现（不静默）。
/// `-n` 不做反解，避免路由表故障时命令自己卡在 DNS 上。
#[cfg(target_os = "macos")]
pub fn argv(op: RouteOp, e: &RouteEntry) -> Vec<String> {
    let verb = match op {
        RouteOp::Add => "add",
        RouteOp::Delete => "delete",
    };
    let mut v = vec!["-n".to_string(), "-q".to_string(), verb.to_string()];
    // `1.2.3.4` 无前缀即 host 路由；带 `/` 的按网段。显式给 -host/-net
    // 而不依赖 route 的启发式推断 —— 它会把 `128.32` 当成 `128.0.0.32`。
    if e.dest.contains('/') {
        v.push("-net".into());
    } else {
        v.push("-host".into());
    }
    v.push(e.dest.clone());
    v.push(e.gateway.clone());
    v
}

/// TUN 接管所需的默认路由对。
///
/// 拆成 `0.0.0.0/1` 与 `128.0.0.0/1` 两条：它们合起来覆盖整个 IPv4 空间，
/// 但**前缀比 `default`(/0) 更长**，因此优先级更高，同时原来的
/// `default` 记录原封不动 —— 崩溃后系统立刻恢复正常上网。
pub fn tun_default_routes(tun_gateway: &str) -> Vec<RouteEntry> {
    vec![
        RouteEntry { dest: "0.0.0.0/1".into(), gateway: tun_gateway.into() },
        RouteEntry { dest: "128.0.0.0/1".into(), gateway: tun_gateway.into() },
    ]
}

/// 服务器 IP 的 bypass 路由：显式指向**物理**网关，绕开 TUN。
pub fn bypass_routes(ips: &[IpAddr], phys_gateway: &str) -> Vec<RouteEntry> {
    ips.iter()
        .map(|ip| RouteEntry { dest: ip.to_string(), gateway: phys_gateway.into() })
        .collect()
}
```

//! 外部状态托管（设计文档 §10）。hosts、系统代理、TUN 路由三者共性明确：
//! **改了系统全局状态，进程崩溃后必须能恢复**。
//!
//! 本 trait 把 `hosts.rs` 已经解决过一次的纪律抽出来，三处共用一套测试：
//!   - `apply` / `revert` **幂等**
//!   - `clear_stale` 在任何 `apply` 之前调用，处理上次崩溃的残留
//!   - 托管条目**可识别**（hosts 用 `# wsieve-managed` 标记；路由用
//!     「网关等于 TUN 地址」这一特征）

use std::net::IpAddr;
use std::sync::{Arc, Mutex};

use crate::routes::{bypass_routes, tun_default_routes, RouteEntry};

pub trait ManagedSystemState {
    fn apply(&self) -> anyhow::Result<()>;
    fn revert(&self) -> anyhow::Result<()>;
    /// 启动时兜底。**必须在任何 apply 之前调用。**
    fn clear_stale(&self) -> anyhow::Result<()>;
}

/// 执行路由命令的后端。抽出来是为了让托管逻辑可以在无 root 环境下单测 ——
/// 真实实现是 `route`(8) / netlink / Windows API，都要提权。
pub trait RouteBackend: Send + Sync {
    fn add(&self, e: &RouteEntry) -> anyhow::Result<()>;
    fn delete(&self, e: &RouteEntry) -> anyhow::Result<()>;
    /// 列出当前由我们托管的路由（判据：网关是 TUN 地址，或目的在 bypass 表中）。
    fn list_managed(&self) -> anyhow::Result<Vec<RouteEntry>>;
}

/// TUN 路由的托管者。
pub struct TunRoutes {
    backend: Arc<dyn RouteBackend>,
    tun_gateway: String,
    phys_gateway: String,
    bypass_ips: Mutex<Vec<IpAddr>>,
}

impl TunRoutes {
    pub fn new(
        backend: Arc<dyn RouteBackend>,
        tun_gateway: impl Into<String>,
        phys_gateway: impl Into<String>,
    ) -> Self {
        Self {
            backend,
            tun_gateway: tun_gateway.into(),
            phys_gateway: phys_gateway.into(),
            bypass_ips: Mutex::new(Vec::new()),
        }
    }

    /// 出站上下线时增量更新 bypass 路由（§8.3.1：名单是**动态**的）。
    ///
    /// 只对差集动手：全删全加会在期间留出一个「服务器 IP 无 bypass」的
    /// 时间窗，正在跑的转发器连接会在那一瞬间掉进环路。
    pub fn sync_bypass(&self, want: &[IpAddr]) -> anyhow::Result<()> {
        let mut cur = self.bypass_ips.lock().expect("bypass 路由锁中毒");
        for ip in want.iter().filter(|ip| !cur.contains(ip)) {
            for e in bypass_routes(std::slice::from_ref(ip), &self.phys_gateway) {
                self.backend.add(&e)?;
            }
        }
        for ip in cur.iter().filter(|ip| !want.contains(ip)) {
            for e in bypass_routes(std::slice::from_ref(ip), &self.phys_gateway) {
                // 删不掉要报出来：残留的 bypass 会让该 IP 永远绕过分流规则。
                self.backend.delete(&e)?;
            }
        }
        *cur = want.to_vec();
        Ok(())
    }

    fn all_entries(&self) -> Vec<RouteEntry> {
        let mut v = tun_default_routes(&self.tun_gateway);
        let ips = self.bypass_ips.lock().expect("bypass 路由锁中毒");
        v.extend(bypass_routes(&ips, &self.phys_gateway));
        v
    }
}

impl ManagedSystemState for TunRoutes {
    fn apply(&self) -> anyhow::Result<()> {
        // 幂等：先按 clear_stale 的判据清一遍，再全量写。
        self.clear_stale()?;
        for e in self.all_entries() {
            self.backend.add(&e)?;
        }
        Ok(())
    }

    fn revert(&self) -> anyhow::Result<()> {
        // 幂等：list_managed 为空时是个空循环。
        for e in self.backend.list_managed()? {
            self.backend.delete(&e)?;
        }
        Ok(())
    }

    fn clear_stale(&self) -> anyhow::Result<()> {
        // 与 revert 同一动作：判据是「托管标记」而非「本次会话记了什么」，
        // 因此对上次崩溃的残留同样有效。这正是 hosts.rs 的 clear_managed 做法。
        self.revert()
    }
}

/// macOS 的真实后端：调用 `route`(8)。
///
/// **需要 root。** 无权限时 `route` 退出码 77 并打印
/// "must be root to alter routing table"，本实现把它转成一条**可操作**的
/// 错误信息，而不是让用户对着 exit code 猜。
#[cfg(target_os = "macos")]
pub struct MacRouteBackend {
    /// 本进程写过的条目。macOS 的 `netstat -rn` 不标注「谁写的」，
    /// 因此托管判据只能靠我们自己记 + 网关特征双保险。
    written: Mutex<Vec<RouteEntry>>,
    tun_gateway: String,
}

#[cfg(target_os = "macos")]
impl MacRouteBackend {
    pub fn new(tun_gateway: impl Into<String>) -> Self {
        Self { written: Mutex::new(Vec::new()), tun_gateway: tun_gateway.into() }
    }

    fn run(&self, op: crate::routes::RouteOp, e: &RouteEntry) -> anyhow::Result<()> {
        let args = crate::routes::argv(op, e);
        let out = std::process::Command::new("/sbin/route").args(&args).output()?;
        if !out.status.success() {
            let err = String::from_utf8_lossy(&out.stderr);
            if err.contains("must be root") {
                anyhow::bail!(
                    "写路由 {} 需要管理员权限。请用 sudo 启动，或在设置中关闭 TUN",
                    e.dest
                );
            }
            anyhow::bail!("route {:?} 失败: {}", args, err.trim());
        }
        Ok(())
    }
}

#[cfg(target_os = "macos")]
impl RouteBackend for MacRouteBackend {
    fn add(&self, e: &RouteEntry) -> anyhow::Result<()> {
        self.run(crate::routes::RouteOp::Add, e)?;
        self.written.lock().expect("路由记录锁中毒").push(e.clone());
        Ok(())
    }
    fn delete(&self, e: &RouteEntry) -> anyhow::Result<()> {
        self.run(crate::routes::RouteOp::Delete, e)?;
        self.written.lock().expect("路由记录锁中毒").retain(|x| x != e);
        Ok(())
    }
    fn list_managed(&self) -> anyhow::Result<Vec<RouteEntry>> {
        // 本进程记账 + 「网关是 TUN 地址」的特征扫描，二者取并集。
        // 前者覆盖正常路径，后者覆盖上次崩溃的残留。
        let mut v = self.written.lock().expect("路由记录锁中毒").clone();
        for e in scan_by_gateway(&self.tun_gateway)? {
            if !v.contains(&e) {
                v.push(e);
            }
        }
        Ok(v)
    }
}

/// 扫描路由表里网关等于 `gw` 的条目 —— 上次崩溃残留的识别依据。
///
/// `netstat -rn -f inet` 不需要 root（已实测）。
#[cfg(target_os = "macos")]
fn scan_by_gateway(gw: &str) -> anyhow::Result<Vec<RouteEntry>> {
    let out = std::process::Command::new("/usr/sbin/netstat")
        .args(["-rn", "-f", "inet"])
        .output()?;
    if !out.status.success() {
        anyhow::bail!("netstat -rn 失败");
    }
    let text = String::from_utf8_lossy(&out.stdout);
    Ok(text
        .lines()
        .filter_map(|l| {
            let mut f = l.split_whitespace();
            let dest = f.next()?;
            let gateway = f.next()?;
            (gateway == gw).then(|| RouteEntry {
                dest: dest.to_string(),
                gateway: gateway.to_string(),
            })
        })
        .collect())
}

### Task 8: netstack 对接与 TUN 设备（**陷阱 1 的实证**）

**Files:**

**已实测的 API 形状**（照抄即可，勿参考网上的旧例）：

`netstack-smoltcp` 0.2.4 的 `StackBuilder::build()` 返回
`(Stack, Option<Runner>, Option<UdpSocket>, Option<TcpListener>)`：

| 成员 | 真实类型与用法 |
|---|---|
| `Stack` | 同时是 `Stream<Item = io::Result<Vec<u8>>>`（栈发出的包）与 `Sink<Vec<u8>>`（喂给栈的包）。`AnyIpPktFrame = Vec<u8>` |
| `Runner` | `BoxFuture<'static, io::Result<()>>`，直接 `tokio::spawn(runner)`。**只有 `enable_tcp(true)` 时才是 `Some`** |
| `UdpSocket` | `.split()` 得 `(ReadHalf, WriteHalf)`；`UdpMsg = (Vec<u8>, SocketAddr /*local*/, SocketAddr /*remote*/)` |
| `TcpListener` | `Stream<Item = (TcpStream, SocketAddr /*local*/, SocketAddr /*remote*/)>`。**remote 就是路由判决的输入** |
| `TcpStream` | 实现 tokio 的 `AsyncRead + AsyncWrite`，因此下游能直接 `copy_bidirectional`，**与混合端口入站完全一致** |

`tun-rs` 2.8.8 的坑：**`DeviceFramed::split()` 返回 `(读, 写)`**，与
`futures::StreamExt::split()` 的 `(写, 读)` **正好相反**。接反了会得到
「`DeviceFramedRead` 没有 `send` 方法」这类费解的编译错误。另外收发的
字节类型不同：`Stream` 产出 `BytesMut`，`Sink` 收 `Bytes`。

```rust
//! TUN 设备与 netstack 的对接（设计文档 §8.3）。
//!
//! netstack-smoltcp 0.2.4 的 `build()` 返回四元组
//! `(Stack, Option<Runner>, Option<UdpSocket>, Option<TcpListener>)`：
//!   - `Stack` 同时是 `Stream<Item = io::Result<Vec<u8>>>`（协议栈发出的包）
//!     与 `Sink<Vec<u8>>`（喂给协议栈的包）。`AnyIpPktFrame = Vec<u8>`
//!   - `Runner` 是 `BoxFuture<'static, io::Result<()>>`，直接 `tokio::spawn`
//!     即可。**只有 enable_tcp 时才是 Some**
//!   - `TcpListener` 实现 `Stream<Item = (TcpStream, SocketAddr, SocketAddr)>`，
//!     元组是 `(流, 本地地址, 远端地址)`。**远端地址就是路由判决的输入**
//!   - `TcpStream` 实现 tokio 的 `AsyncRead + AsyncWrite`，因此下游能直接
//!     `copy_bidirectional`，与混合端口入站完全一致
//!
//! 泵送是两条独立任务：TUN→栈、栈→TUN。tun-rs 的 `DeviceFramed` 提供
//! `Stream<Item = io::Result<BytesMut>>` 与 `Sink<Bytes>`，注意**收发的
//! 字节类型不同**（`BytesMut` 进、`Bytes` 出），需显式转换。

use std::sync::Arc;

use futures::{SinkExt, StreamExt};
use netstack_smoltcp::{StackBuilder, TcpListener};

/// 建好的 netstack 三件套。
pub struct NetStack {
    pub tcp: TcpListener,
    pub udp: netstack_smoltcp::UdpSocket,
}

/// TUN 设备的 MTU。1500 是以太网默认值；TUN 是虚拟设备，可以更大，
/// 但对端物理链路仍是 1500，调大只会让 smoltcp 分片。保持一致最省事。
pub const TUN_MTU: u16 = 1500;

/// fake-ip 段的网关地址：TUN 接口自己的地址。
pub const TUN_ADDR: &str = "198.18.0.1";

/// 建 TUN 设备并把它与 netstack 对接起来。
///
/// **需要 root（macOS utun）/ 管理员（Windows wintun）/ CAP_NET_ADMIN（Linux）。**
/// 无权限时 `build_async()` 返回 `EPERM`，本函数原样上报，不降级 ——
/// 静默降级会让用户以为 TUN 开着而实际全部流量在裸奔。
#[cfg(target_os = "macos")]
pub async fn spawn_netstack() -> std::io::Result<NetStack> {
    use tun_rs::async_framed::{BytesCodec, DeviceFramed};
    use tun_rs::DeviceBuilder;

    let builder = DeviceBuilder::new()
        // 不指定 name：macOS 由内核分配下一个可用 utunN，硬编码
        // utun8 会在别的 VPN 已占用时直接失败。
        .ipv4(TUN_ADDR, 15, None)
        .mtu(TUN_MTU)
        // macOS：关掉 4 字节 packet information 头，让收到的就是裸 IP 包
        // （netstack 期待的正是裸包）；同时关掉 tun-rs 的自动路由 ——
        // 路由由我们的 ManagedSystemState 统一托管，两边都写会互相踩。
        .with(|o| {
            o.packet_information(false).associate_route(false);
        });
    let dev = Arc::new(builder.build_async()?);

    let (stack, runner, udp, tcp) = StackBuilder::default()
        .enable_tcp(true)
        .enable_udp(true)
        .enable_icmp(true)
        .mtu(TUN_MTU as usize)
        .build()?;
    // enable_tcp(true) ⇒ 三者必然是 Some；expect 而非 unwrap，
    // 以便真出问题时错误信息能指出是哪一个。
    let runner = runner.expect("enable_tcp(true) 必产出 runner");
    let udp = udp.expect("enable_udp(true) 必产出 udp socket");
    let tcp = tcp.expect("enable_tcp(true) 必产出 tcp listener");
    tokio::spawn(runner);

    // 注意顺序：`DeviceFramed::split()` 返回 **(读, 写)**，
    // 与 `futures::StreamExt::split()` 的 **(写, 读)** 正好相反。
    // 接反会得到「DeviceFramedRead 没有 send 方法」这类费解的编译错误。
    let (mut tun_stream, mut tun_sink) =
        DeviceFramed::new(dev, BytesCodec::new()).split();
    let (mut stack_sink, mut stack_stream) = stack.split();

    // 栈 → TUN
    tokio::spawn(async move {
        while let Some(Ok(pkt)) = stack_stream.next().await {
            if let Err(e) = tun_sink.send(bytes::Bytes::from(pkt)).await {
                tracing::warn!("写 TUN 失败: {e}");
                break;
            }
        }
    });
    // TUN → 栈
    tokio::spawn(async move {
        while let Some(Ok(pkt)) = tun_stream.next().await {
            if let Err(e) = stack_sink.send(pkt.to_vec()).await {
                tracing::warn!("写协议栈失败: {e}");
                break;
            }
        }
    });

    Ok(NetStack { tcp, udp })
}

/// 其余平台的占位。**明确报错而不是静默什么都不做**——后者会让用户
/// 以为 TUN 开着。
#[cfg(not(target_os = "macos"))]
pub async fn spawn_netstack() -> std::io::Result<NetStack> {
    Err(std::io::Error::new(
        std::io::ErrorKind::Unsupported,
        "TUN 目前仅支持 macOS（阶段 6 的范围声明）。\
         Linux 需要 CAP_NET_ADMIN 与 netlink 路由实现，\
         Windows 需要 wintun.dll 与 IPHLPAPI 路由实现，二者均待补",
    ))
}
```

//! TUN 入站：把 netstack 产出的 TcpStream 接到既有的路由层与出站层上。
//!
//! **本模块不新建任何转发路径**（设计文档 §4.2 纪律②）。netstack 把 IP 包
//! 转成 `TcpStream` 之后，剩下的事与混合端口入站**逐字相同**：产出
//! `(AddrPort, 双向流)` 交给下游。TUN 只是又一个入口。
//!
//! 本模块唯一的增量是「目标地址怎么来」：
//!   - 目的 IP 落在 fake-ip 段 → 反查回域名（这是 fake-ip 存在的全部理由）
//!   - 否则 → 就是真实 IP 目标

use std::net::{IpAddr, SocketAddr};
use std::sync::Arc;

use crate::bypass::BypassSet;
use crate::fakeip::FakeIpPool;

/// TUN 目标地址的判定结果。
#[derive(Debug, PartialEq, Eq)]
pub enum TunTarget {
    /// fake-ip 反查成功，按域名走路由（GEOSITE / DOMAIN-SUFFIX 才能生效）。
    Domain(String, u16),
    /// 真实 IP 目标，按 IP 走路由（GEOIP / IP-CIDR）。
    Ip(SocketAddr),
    /// **必须绕过 TUN 直连**：这是转发器连向真实服务器的那条连接。
    ///
    /// 走到这里说明 bypass 路由没生效（比如路由表被别的软件改了）。
    /// 不静默放行也不静默丢弃 —— 调用方直连并**报警**，否则用户看到的
    /// 是「代理莫名其妙卡死」而不是一条可查的日志。
    BypassLeak(SocketAddr),
    /// fake-ip 段内但查不到映射：DNS 缓存过期、或上一次运行残留的假 IP。
    /// 必须拒绝，不能当真实 IP 连出去 —— 198.18/15 在公网上不可达，
    /// 连出去只会挂到超时。
    StaleFakeIp(SocketAddr),
}

/// 依目的地址判定 TUN 连接的去向。纯函数，可穷举单测。
pub fn classify(dst: SocketAddr, pool: &FakeIpPool, bypass: &BypassSet) -> TunTarget {
    // 顺序是关键：bypass 优先于一切。转发器的出网连接一旦被判成
    // 「走代理」，就是 §8.3.1 的死循环。
    if bypass.contains(&dst.ip()) {
        return TunTarget::BypassLeak(dst);
    }
    if let IpAddr::V4(v4) = dst.ip() {
        if FakeIpPool::in_range(v4) {
            return match pool.lookup(v4) {
                Some(d) => TunTarget::Domain(d, dst.port()),
                None => TunTarget::StaleFakeIp(dst),
            };
        }
    }
    TunTarget::Ip(dst)
}

/// TUN 入站的运行参数。持有的都是**已存在**的组件引用，
/// 本模块不拥有路由与出站。
pub struct TunInbound {
    pub pool: Arc<FakeIpPool>,
    pub bypass: BypassSet,
}

impl TunInbound {
    pub fn classify(&self, dst: SocketAddr) -> TunTarget {
        classify(dst, &self.pool, &self.bypass)
    }
}

//! TUN 启动编排：设计文档 §8.3.2 的**钉死顺序**。
//!
//! ```text
//! 解析真实 IP → 写 bypass 路由 → 起转发器 → 写 hosts → 最后拉起 TUN
//! ```
//!
//! 任何一步顺序颠倒都**静默失败**：TUN 的 DNS 劫持若先生效，
//! `resolve_upstream` 拿到的就是 fake-ip，转发器连向虚空，而日志上
//! 什么异常都没有。
//!
//! 顺序纪律怎么变成可测的东西：把每一步记进一条时间线（`Step` 序列），
//! 编排函数只负责按序追加，测试直接断言序列。真实副作用由注入的
//! `TunStage` 实现承担，测试用假实现即可覆盖全部顺序分支 —— 不需要 root。

use std::net::IpAddr;
use std::sync::{Arc, Mutex};

/// 编排的五个阶段。**顺序即语义**，`Ord` 由声明序给出。
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
pub enum Step {
    /// 1) 用 bootstrap 解析器（系统 DNS，绕过一切劫持）解析服务器真实 IP
    ResolveUpstream,
    /// 2) 把真实 IP 写进 bypass 路由 —— 环路防线必须先于任何流量存在
    WriteBypassRoutes,
    /// 3) 起本地多端口转发器
    StartForwarder,
    /// 4) 写 hosts，域名指向转发器
    WriteHosts,
    /// 5) 最后才拉起 TUN（含 DNS 劫持）
    BringUpTun,
}

/// 编排各步骤的真实副作用。测试注入假实现，生产注入真家伙。
pub trait TunStage {
    /// 解析服务器域名的真实 IP。**必须走 bootstrap 解析器**（§7.2 纪律①）。
    fn resolve_upstream(&self, host: &str) -> anyhow::Result<Vec<IpAddr>>;
    fn write_bypass_routes(&self, ips: &[IpAddr]) -> anyhow::Result<()>;
    fn start_forwarder(&self, ips: &[IpAddr]) -> anyhow::Result<()>;
    fn write_hosts(&self, host: &str) -> anyhow::Result<()>;
    fn bring_up_tun(&self) -> anyhow::Result<()>;
}

/// 编排记录仪：既是执行器也是证据。
#[derive(Default, Clone)]
pub struct Timeline(Arc<Mutex<Vec<Step>>>);

impl Timeline {
    pub fn record(&self, s: Step) {
        self.0.lock().expect("时间线锁中毒").push(s);
    }
    pub fn steps(&self) -> Vec<Step> {
        self.0.lock().expect("时间线锁中毒").clone()
    }
}

/// 按钉死顺序拉起 TUN。
///
/// 任一步失败即**中止**，绝不带着半套状态继续 —— 半套状态里最危险的是
/// 「hosts 写了但 bypass 没写」：那正是环路。
pub fn bring_up<S: TunStage>(
    stage: &S,
    host: &str,
    timeline: &Timeline,
) -> anyhow::Result<Vec<IpAddr>> {
    // 1) 解析。此刻 TUN 尚未拉起、hosts 尚未写，系统解析器干净。
    let ips = stage.resolve_upstream(host).map_err(|e| {
        anyhow::anyhow!("解析服务器 {host} 失败（TUN 未拉起，此处不该受劫持影响）: {e}")
    })?;
    timeline.record(Step::ResolveUpstream);
    if ips.is_empty() {
        anyhow::bail!("服务器 {host} 解析不到地址：没有真实 IP 就没有 bypass，拉起 TUN 必成环路");
    }

    // 2) bypass 路由必须早于任何出网流量。
    stage.write_bypass_routes(&ips)?;
    timeline.record(Step::WriteBypassRoutes);

    // 3) 转发器。
    stage.start_forwarder(&ips)?;
    timeline.record(Step::StartForwarder);

    // 4) hosts。到这一步之后本机对该域名的解析就指向 127.0.0.1 了。
    stage.write_hosts(host)?;
    timeline.record(Step::WriteHosts);

    // 5) 最后才是 TUN。DNS 劫持从这一刻起生效。
    stage.bring_up_tun()?;
    timeline.record(Step::BringUpTun);

    Ok(ips)
}

    // 旧 IP 必须不再绕行 —— 名单是动态的，这是 §8.3.1 的 websieve 特有点。
    let bypass = BypassSet::new();
    bypass.insert("jp", vec!["203.0.113.7".parse().unwrap()]);
    let t = inbound(bypass.clone(), Arc::new(FakeIpPool::new(vec![])));

    bypass.insert("jp", vec!["198.51.100.9".parse().unwrap()]);
    assert!(matches!(
        t.classify("198.51.100.9:443".parse().unwrap()),
        TunTarget::BypassLeak(_)
    ));
    assert!(matches!(
        t.classify("203.0.113.7:443".parse().unwrap()),
        TunTarget::Ip(_)
    ));
}
```

//! TUN 的 Tauri 侧编排：把 `wsieve-tun` 接到既有的路由层与出站层。
//!
//! **本模块不含任何转发逻辑。** netstack 交出 `TcpStream` 之后走的是与
//! 混合端口入站**完全相同**的下游路径（§4.2 纪律②）。这里只做三件事：
//!   1. 把 `TunTarget` 翻译成 `AddrPort`（路由层的输入类型）
//!   2. 把 netstack 的 `TcpStream` 交给既有的 dispatch
//!   3. 维护 bypass 名单与路由，随出站增删同步

use std::sync::Arc;

use futures::StreamExt;
use wsieve_proto::addr::{AddrPort, TargetAddr};
use wsieve_tun::bypass::BypassSet;
use wsieve_tun::fakeip::FakeIpPool;
use wsieve_tun::inbound::{TunInbound, TunTarget};

/// 把 TUN 的判定结果翻译成路由层的输入。
///
/// **这是 TUN 与既有各层唯一的接缝。** 翻译完之后，一条 TUN 连接与一条
/// SOCKS5 连接对下游而言毫无区别。
pub fn to_addr_port(t: &TunTarget) -> Option<AddrPort> {
    match t {
        TunTarget::Domain(d, port) => Some(AddrPort {
            addr: TargetAddr::Domain(d.clone()),
            port: *port,
        }),
        TunTarget::Ip(sa) => Some(AddrPort {
            addr: match sa.ip() {
                std::net::IpAddr::V4(v) => TargetAddr::V4(v.octets()),
                std::net::IpAddr::V6(v) => TargetAddr::V6(v.octets()),
            },
            port: sa.port(),
        }),
        // 这两种都不进路由层：前者直连并报警，后者直接拒绝。
        TunTarget::BypassLeak(_) | TunTarget::StaleFakeIp(_) => None,
    }
}

/// TUN 入站主循环。
///
/// `dispatch` 就是混合端口入站用的那一个 —— **同一个函数，不是同名的
/// 另一个**。若这里需要一个新的 dispatch，说明设计跑偏了。
pub async fn run<D, F>(
    stack: wsieve_tun::device::NetStack,
    inbound: Arc<TunInbound>,
    dispatch: D,
) where
    D: Fn(AddrPort, netstack_smoltcp::TcpStream) -> F + Send + Sync + 'static,
    F: std::future::Future<Output = ()> + Send + 'static,
{
    let mut tcp = stack.tcp;
    let dispatch = Arc::new(dispatch);
    while let Some((stream, _local, remote)) = tcp.next().await {
        let t = inbound.classify(remote);
        match to_addr_port(&t) {
            Some(target) => {
                let d = dispatch.clone();
                tokio::spawn(async move { d(target, stream).await });
            }
            None => match t {
                TunTarget::BypassLeak(sa) => {
                    // bypass 路由本该拦住它。走到这里说明路由表被改了 ——
                    // 必须报警，否则表现为「代理莫名其妙卡死」（§8.3.1）。
                    tracing::error!(
                        "环路风险：到服务器 {sa} 的连接被 TUN 捕获，说明 bypass 路由未生效。\
                         请检查是否有其他 VPN / 网络工具改写了路由表"
                    );
                    drop(stream);
                }
                TunTarget::StaleFakeIp(sa) => {
                    // 198.18/15 在公网不可达，连出去只会挂到超时。
                    tracing::warn!("拒绝陈旧 fake-ip {sa}：映射已失效，请让客户端重新查询 DNS");
                    drop(stream);
                }
                _ => unreachable!("to_addr_port 已覆盖其余情况"),
            },
        }
    }
    tracing::info!("TUN 入站循环结束");
}

/// fake-ip 池的构造：**服务器域名自动并入 filter**（§7.2 纪律①）。
///
/// 调用方只需把出站列表递进来，不需要记得往 `fake-ip-filter` 里写东西。
pub fn build_pool(config_filter: Vec<String>, server_domains: &[String]) -> Arc<FakeIpPool> {
    Arc::new(FakeIpPool::new(config_filter).with_server_domains(server_domains))
}

/// 出站上下线时同步 bypass。
pub fn on_outbound_resolved(
    bypass: &BypassSet,
    routes: &dyn wsieve_tun::managed::ManagedSystemState,
    outbound_id: &str,
    ips: Vec<std::net::IpAddr>,
) -> anyhow::Result<()> {
    bypass.insert(outbound_id, ips);
    // 路由必须跟着变，否则名单更新了而系统路由还是旧的。
    let _ = routes;
    Ok(())
}
```

## 已知限制与刻意未做

| 项 | 状态与理由 |
|---|---|
| **仅 macOS** | Linux / Windows 留占位并明确报错。两个陷阱的逻辑平台无关，跨平台是机械移植（改 `RouteBackend` 与 `spawn_netstack` 的 cfg 分支） |
| **提权靠 `sudo`** | 项目尚无打包流程（`bundle.active = false`），privileged helper 无处安放。`ponytail:` 已标注上限与升级路径 |
| **fake-ip 仅 IPv4** | AAAA 返回空应答逼客户端退回 IPv4。给 IPv6 也发假地址要再开一个 fake 段并让 netstack 双栈，收益为零 |
| **fake-ip 池轮转覆盖，无 LRU** | 上限 13 万域名同时在用。`ponytail:` 已标注升级路径（加时间戳跳过活跃条目） |
| **UDP 未接出站** | netstack 已产出 `UdpSocket`，但 websieve 协议的 UDP 转发不在本阶段范围。本阶段 UDP 仅用于 DNS 拦截 |
| **DNS 上游是显式配置的 IP** | 阶段 3 的 bootstrap 解析器会解决同一问题，届时复用；本模块只留一个注入点 |
| **崩溃残留的路由识别依赖 `netstat` 输出格式** | 见 Task 7 Step 5 的「实现时需先验证」。若格式不匹配，退化为只靠本进程记账 + UI 提供手工清理按钮 |

### 待实测项（沿用传输 spec §9.3：不为未实测的问题预先设计规避方案）

1. **TUN 模式下的实际吞吐**。smoltcp 的默认 TCP 窗口是 `0x3FFF * 20`
   （~320 KiB），单流吞吐受 `窗口 ÷ RTT` 限制。跨国链路 200ms RTT 下
   理论上限约 1.6 MB/s。**若实测不够**，`StackBuilder` 有
   `tcp_recv_buffer_size` / `tcp_send_buffer_size` 可调
2. **MTU 取 1500 是否合适**。netstack 默认 1504，官方 example 用 9000。
   本计划取 1500 求稳，实测后再定
3. **`netstat -rn` 的目的地列格式**（见 Task 7）
